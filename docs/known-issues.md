# Known Issues and Landmines

Defects and traps that cost real time during planning, recorded so they do not
cost time again during the event.

Scope: things that are true of the toolchain regardless of which stack the
problem analysis selects. These are not product bugs. Nothing here is currently
broken in this repository.

Severity reflects how much event time the issue costs, not how hard it is to
fix.

---

## 1. ESLint 10 crashes `eslint-config-next`

**Severity:** high. Costs roughly 30 minutes of confused debugging, because the
error does not mention either version.

**Affects:** any Next.js project generated by the current `create-next-app` or
`shadcn init` scaffold.

**Symptom**

```
TypeError: Error while loading rule 'react/display-name':
  contextOrFilename.getFilename is not a function
```

ESLint reports this as an internal crash, not as a lint failure, so it reads as
a corrupt install rather than a version conflict. Every `npm run lint` exits
non-zero.

**Cause**

The generated `package.json` pins `eslint: ^10`. `eslint-config-next` declares
`peerDependencies.eslint: ">=9.0.0"`, which wrongly admits 10, so npm accepts
the combination without complaint. But the `eslint-plugin-react` that
`eslint-config-next` bundles still calls `context.getFilename()`, which ESLint
removed in version 10.

**Earlier signal, ignored**

`npm install` prints `ERESOLVE overriding peer dependency` several times. That
warning is the conflict announcing itself. Treat it as a stop-and-read, not
noise.

**Fix**

Pin ESLint 9:

```bash
npm install --save-dev "eslint@^9.39.5"
```

Verified: with the pin, `typecheck`, `lint`, and `build` all exit 0 on a
Next.js 16.3.4 project.

## 2. A bare `postgresql://` URL makes SQLAlchemy import psycopg 2

**Severity:** high. Produces an error that looks like a database outage.

**Affects:** FastAPI or any other project using SQLAlchemy 2 with `psycopg` 3.

**Symptom**

```
sqlalchemy/dialects/postgresql/psycopg2.py
ModuleNotFoundError: No module named 'psycopg2'
```

Raised from `create_engine`, so it fires at import time. No connection is
attempted and no database is involved.

**Cause**

Two independent issues collapse into one confusing error:

1. `psycopg2` (driver version 2) and `psycopg` (driver version 3) are different
   packages with similar names. Installing `psycopg[binary]` gives you v3 only.
2. A URL with no explicit driver, `postgresql://`, makes SQLAlchemy default to
   the v2 driver.

**Fix**

Name the driver explicitly: `postgresql+psycopg://user:pass@host:5432/db`.

Also normalise the legacy `postgres://` scheme, which Railway and Heroku inject
and which SQLAlchemy 2 removed. Both cases become `postgresql+psycopg://`.

Normalise once, in settings, not at each call site. Regression-test it: without
a test, the next person deletes the validator as unnecessary.

## 3. Playwright writes artifacts into the working tree

**Severity:** medium. Silent, and it accumulates across a whole event.

**Affects:** any repository where the Playwright MCP server runs.

**Symptom**

A `.playwright-mcp/` directory appears at the repository root, containing
timestamped page snapshots (`page-<ISO>.yml`) and console logs
(`console-<ISO>.log`). One directory per session, files per run.

**Cause**

The Playwright MCP server writes its artifacts relative to its working
directory. It does not check `.gitignore` and does not ask.

**Consequence**

Once a repository exists, these get committed. The log files can contain
console output from pages displaying environment data, which is a data
exposure rather than merely untidiness.

**Fix**

Already applied to this repository's `.gitignore`. Carry it into any project
created during the event:

```gitignore
# Playwright
playwright-report/
test-results/
.playwright-mcp/
blob-report/
.playwright/
```

## 4. `shadcn init` requires a TTY and cannot be automated

**Severity:** medium, but only if an agent is driving the setup.

**Affects:** `shadcn init` with a Next.js template.

**Symptom**

The command reports `-y` and `-d` and then stops at a prompt. With piped
input it clears the first prompt and hangs on the second, which is an arrow-key
preset selector that piped input cannot satisfy. From an agent or a CI runner
it produces no output and no project.

**Fix**

Do not run a scaffolding generator during the event if an agent is driving.
Write the configuration files by hand, or run the generator once interactively
before the event and keep the result as the starting point.

`npx shadcn@latest add button card input` only asks for component names, so it
is safe to run non-interactively.

## 5. The stock Next.js `.gitignore` swallows `.env.example`

**Severity:** low. Costs a confused moment, not a lost feature.

**Cause**

The generated `.gitignore` uses a bare `.env*`, which also matches
`.env.example`. The example file is the documented variable list, and it is the
first thing a new teammate reads to configure the project.

**Fix**

```gitignore
.env
.env.*
!.env.example
```

Keep the negation if the file is ever regenerated.

## 6. `NEXT_PUBLIC_` variables are inlined at build time

**Severity:** medium during deployment, not during development.

**Symptom**

A variable is set correctly in the deployment dashboard, but the deployed app
still uses the old value, or still points at `localhost`.

**Cause**

`NEXT_PUBLIC_`-prefixed variables are substituted into the client bundle when
the build runs. Changing the value afterwards does not alter already-built
assets, so a redeploy that reuses a build cache keeps the old value.

**Rules that follow**

1. Redeploy after changing any `NEXT_PUBLIC_` value. Changing the dashboard is
   not enough.
2. Never put a secret behind the prefix. The value is readable by anyone who
   loads the page.
3. A server-side API URL read at request time avoids the whole class of
   problem. That is the argument for a same-origin server route proxy over
   direct browser calls.
